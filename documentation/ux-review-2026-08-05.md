# Pairc — Visual / UX / UI Review

**Date:** 2026-08-05
**Method:** Live app driven in Chromium at 390×844 (phone), 1024×768 (tablet), 1512×900 (desktop), seeded with `tests/fixtures/simulatedMatch.js` plus turnovers. All findings below are measured from the running app, not read off the source.
**Scope:** Login, Capture, Match picker, Live, Digest, Kickouts, Shots, Turnovers, Events, Possession Analysis, Pass Destination, Tactical Board.

---

## Verdict

The design language is genuinely good. The Tactical Board and the Live panel are the strongest screens in the app — confident typography, real information hierarchy, restrained colour. The analytics panels are dense but organised, and the visual grammar in `documentation/visual-language.md` is a real asset.

The problem is that this quality is not evenly distributed, and the **primary capture screen is non-functional at phone widths** — on a product whose README opens with the words "mobile-first". That single defect outweighs everything else in this document.

Below: launch blockers first, then the rest by severity.

---

## 1. Launch blockers

### 1.1 The capture screen is unusable on a phone

At 390×844 (and 360×740, and 428×926) the capture screen cannot be used at all:

| Measurement | Value |
|---|---|
| `.pitch-card svg` height | **0 px** |
| `.pitch-card svg` top | **1148 px** (viewport is 844 px) |
| `Save Event` button top | **894 px** — below the fold |
| `.form-panel` height | 811 px |
| `.capture-layout` height | **444 px**, `overflow: hidden` |
| `.form-panel` scrollHeight | 810 px — nothing to scroll |

The pitch has zero height and sits ~300 px below the viewport. `Save Event` is clipped by an `overflow: hidden` parent and is not scrollable into view. **You cannot tap the pitch and you cannot save an event.**

Cause — [App.svelte:3877-3890](src/App.svelte#L3877-L3890):

```css
.capture-layout { flex: 1; display: flex; flex-direction: column; overflow: hidden; min-height: 0; }
.form-panel { overflow-y: auto; ...; flex-shrink: 0; ... }
```

Below 768 px the layout is a column, `.form-panel` is `flex-shrink: 0` with no height cap, so it takes its full 811 px content height and pushes `.pitch-panel` (`flex: 1`) to 20 px of padding and the pitch itself to zero. Above 768 px the layout flips to a row and everything works.

Why it was never caught: [layout.spec.js:26](tests/e2e/layout.spec.js#L26) pins the suite to `viewport: { width: 1366, height: 768 }`. The "landscape capture keeps the save controls reachable" test asserts exactly the thing that is broken — but only in landscape. **There is no portrait-phone layout test anywhere in the e2e suite.**

Fix direction: give `.form-panel` a bounded height in the column layout (`flex: 1 1 auto; min-height: 0`) so it scrolls internally, and give `.pitch-panel` a guaranteed minimum. Then add a 390×844 case to `layout.spec.js` asserting the pitch has non-zero height and `Save Event` is in view.

### 1.2 Header text collides with the logo, and doubles in height

Also at 390 px, with a match loaded:

- The header grows from its `min-height: 54px` to **120 px** — 14% of the viewport, before the 46 px tab bar.
- The score renders as `1-` / `4` / `1-` / `4` on four separate lines.
- With no events yet, "Clontarf v Vincents" renders **directly on top of** the crest and the "Páirc" wordmark. Two overlapping strings, unreadable.

Cause — [App.svelte:3480](src/App.svelte#L3480) and [3586-3587](src/App.svelte#L3586-L3587). `.header-center` is `flex: 1`, but `.period-pills` and `.header-actions` are both `flex-shrink: 0`, so at narrow widths `.header-center` is squeezed to near-zero and `.match-score` (no `white-space: nowrap`, no `min-width` floor) wraps character by character.

Fix direction: below ~640 px, drop the match context and score from the header entirely — both are already shown in the match context bar and the Live panel. Or make the whole header centre `min-width: 0; overflow: hidden` with the score `nowrap`.

## 2. High severity

### 2.1 Sticky Save bar covers the jersey grid on desktop

At 1512×900 the `TARGET PLAYER` label renders with nothing under it — the 1–15 grid appears to be missing. It is not: it is behind the sticky action row.

| Element | Rect |
|---|---|
| `.jersey-grid` | y 598 → 691 |
| `Save Event` (sticky) | y 598 → 641 |

[CaptureForm.svelte:959-965](src/lib/CaptureForm.svelte#L959-L965) sets `.action-row { position: sticky; bottom: 0 }` inside `@media (min-width: 768px) and (max-height: 940px)`, with a white gradient background — but the scroll container gets no compensating `padding-bottom`. Jersey numbers 1–5 are occluded and unclickable at rest. Any laptop at 900 px or below hits this.

### 2.2 Focus indicators are absent or invisible on core controls

Tabbing through the capture form, the type/team/period segmented controls (`.seg-top`, `.seg-dir`) report `outline-width: 0px` and `box-shadow: none` when focused — no visible focus state at all. WCAG 2.4.7 failure on the most-used controls in the app.

Repo-wide, `:focus-visible` is defined in exactly **two** files — [Pitch.svelte:327](src/lib/Pitch.svelte#L327) and [TacticalBoard.svelte:1894](src/lib/TacticalBoard.svelte#L1894). Everything else either inherits the UA default or explicitly kills it. Eight `outline: none` declarations across the codebase; some substitute a border-colour change only, e.g. [App.svelte:3814](src/App.svelte#L3814):

```css
.setup-grid input:focus { outline: none; border-color: #1c3f8a; background: #fff; }
```

A 1.5 px border going grey → navy is not a sufficient focus indicator.

### 2.3 Text contrast failures, including the selected state of the main control

Measured against WCAG AA:

| Element | Colours | Ratio | Needs |
|---|---|---|---|
| `.seg-btn.active` — **selected** capture option | `#fff` on `#0a5`, 12 px | **3.05** | 4.5 |
| `.section-btn` / `.tab-btn` inactive — main nav | `#b0b8c4` on `#fff`, 14 px | **2.00** | 4.5 |
| `.re-hint` "Tap to edit" | `#d1d5db` on `#fafafa` | **1.41** | 4.5 |
| `.re-period` / `.re-clock` / `.re-muted` — recent events data | `#9ca3af` on `#fafafa` | **2.43** | 4.5 |
| `.jersey-custom-label` "Other #" | `#9ca3af` on `#fff` | **2.54** | 4.5 |
| `.pills-label` + inactive period pills | `rgba(255,255,255,.38)` on `#0f1923` | **~3.4** | 4.5 |
| `.seg-top` / `.seg-dir` inactive | `#6b7280` on `#f3f4f6` | **4.39** | 4.5 |

Two of these matter more than the numbers suggest. `.seg-btn.active` is the *selected* state of the control an analyst hits dozens of times per match — it needs to read instantly, and at 3.05:1 in bright outdoor light it will not. `.section-btn` at 2.00:1 means the top-level navigation ("In-game", "Tools") is barely visible; several people will not find the analytics tabs at all.

The recent-events row is the other one: period, clock and jersey number are *match data*, not chrome, and they are rendered at 2.43:1.

### 2.4 Touch targets below 44 px throughout the capture form

Measured at 390 px:

- `.jersey-btn` (player numbers 1–15): **68 × 32 px**
- `.seg-btn` (contest, outcome, restart): **87 × 37 px**

Both fall short of the 44 × 44 minimum. This is a one-handed, glance-down, pitch-side app used under time pressure — 32 px number keys will produce mis-taps, and a mis-tapped jersey number is a silent data error nobody notices until the digest.

### 2.5 Document structure is invisible to assistive tech

The entire app exposes:

- **One heading**: `<h1>Páirc</h1>`. "Live Match State", "Kickouts", "Events", "Possession Analysis" — all `div`s. A screen-reader user gets no document outline anywhere.
- **No `<main>` landmark.** Landmarks are `header`, `nav`, and one `svg[role=application]`.
- **No tab semantics.** `role="tablist"` / `role="tab"` / `aria-selected` count: **0**. The three-level navigation is plain buttons, so there is no arrow-key movement and no announcement of the selected tab.
- 2 inputs with no accessible label.

`tests/e2e/accessibility.spec.js` exists but clearly is not covering structure.

## 3. Medium severity

### 3.1 "TEAM" and "OUTCOME" are two identical-looking controls, one above the other

On the capture form, with a match loaded:

```
TEAM      [ Clontarf ] [ Vincents ]
...
OUTCOME   [ Clontarf •ON ] [ Vincents ]
```

Same two labels, same widths, ~200 px apart, meaning completely different things (whose kickout it was vs. who won it). During live capture this is a genuine mis-entry risk, and a mis-entry here inverts the headline retention stat. Give the outcome row verbs — "Won by Clontarf" / "Won by Vincents", or "Retained" / "Lost".

The little `ON` pill inside the selected outcome button is also doing nothing a selected segmented control doesn't already say, and it is white-on-white where it overlaps the button edge.

### 3.2 Two different period controls on the same screen

The header has `Phase: H1 H2 ET All` (a *filter* over analytics). The capture form has `PERIOD: H1 H2 ET` (an *attribute* of the event being recorded). Same values, same visual family, ~300 px apart, opposite semantics. The header one carries an explanatory `title` attribute — which never appears on touch.

The persistent `Showing all periods in this view.` banner on every analytics tab is the app apologising for this ambiguity rather than resolving it.

### 3.3 Three different "primary button" colours

| Screen | Primary action | Fill |
|---|---|---|
| Login | Sign in | `#1c3f8a` |
| Capture | Save Event | `#1c3f8a` |
| Match picker | New match / Create | `#0f1923` |
| Digest | Share image | `#1d4ed8` |

Plus the Login primary is `opacity: 0.5` while disabled ([Login.svelte:134-135](src/lib/Login.svelte#L134-L135)), so the first thing a new user sees is a washed-out CTA that reads as broken.

### 3.4 The design system is entirely ad hoc

- **144 distinct hard-coded hex values** across `App.svelte` + `src/lib/*.svelte`.
- **Zero CSS custom properties** outside `TacticalBoard.svelte`, which defines its own private `--tb-*` set.
- **14 distinct `border-radius` values**: 2, 3, 4, 5, 6, 7, 8, 9, 10, 12, 14, 16, 99, 999 px.
- At least 6 blues in "primary" roles (`#1c3f8a`, `#1d4ed8`, `#2563eb`, `#3b82f6`, `#1e40af`, `#1e3a8a`) and 8+ greens (`#0a5`, `#16a34a`, `#15803d`, `#166534`, `#1a6b22`, `#2d5a33`, `#3d7642`, `#1f5d30`).

Nothing here is individually wrong, but there is no single place to fix the contrast issues in §2.3, and no way to keep the next screen consistent. A `:root` token set (8–10 colours, 4 radii, 5 type sizes) is the highest-leverage refactor in this document.

### 3.5 Colour-only encoding in the Live panel

"Recent scores" renders as circles labelled `P` or `G` — **red for them, green for us, with no legend and no other differentiator**. Red/green is precisely the pair ~8% of men cannot distinguish, and GAA analysts skew male. The kickout battle row below it gets this right (`U` / `T` letters differ), which makes the scores row look like an oversight rather than a decision.

Also: the strip shows 8 chips while the caption reads "They have 7 of the last 10 points." Chip count and caption disagree.

### 3.6 The pitch is the wrong size on every screen except the phone

- **Tablet (1024)** and **desktop (1512)**: on Kickouts/Shots/Turnovers the pitch renders ~670–850 px wide inside a ~1930 px card. The left and right thirds of the card are empty white. The legend sits far below the pitch it describes.
- **Desktop capture**: the pitch SVG is centred inside a `#3d7642` card, leaving two hard-edged darker-green bands down either side. It reads as a rendering artifact, not as design.
- **Phone**: on Kickouts and Shots the pitch overflows its card and requires horizontal scrolling — but on Turnovers it fits. Same component, inconsistent behaviour.

### 3.7 Coincident markers vanish

Kickouts tab: header reads "11 events", pitch shows **2 dots**. Shots: "10 events", **4 dots**. Events at identical coordinates stack perfectly with no count badge, no jitter, no opacity accumulation. Multiple kickouts to the same zone is the normal case in a real match, so the dots view systematically under-represents exactly the pattern the analyst is looking for.

### 3.8 Shot outcome colours are too close to separate

The Shots legend runs Goal (green) → Point (teal) → Wide (amber) → Blocked (orange-red) → Saved (slate). Goal-vs-Point and Wide-vs-Blocked are adjacent hues at ~12 px dot size. The single most important distinction in the whole app — goal or point — is carried by green vs teal. `documentation/visual-language.md` also says "ring = goal attempt", but every dot currently renders with a white ring as its base style, so the ring encoding is unreadable.

### 3.9 Events table puts destructive actions first

At 390 px the table's first column is `ACTIONS` — Edit and **Delete** — while date, period and clock are scrolled off to the right. The most destructive control occupies the most reachable position, and the identifying information you would use to decide *which* row to delete is off-screen. Delete is also styled with the same weight as Edit.

The `Delete all (26)` button plus its nowrap warning ("Use with care — Undo can restore only the most recent wipe.") overflow their scroll container, so the button starts off the left edge of the screen.

## 4. Lower severity / polish

- **No `prefers-reduced-motion` support anywhere** (0 rules), while the app runs an infinite `timerPulse` animation and a `pitchFlash` error animation.
- **No `prefers-color-scheme` support** (0 rules). The header, Live panel and Tactical Board are already dark; a genuine dark mode is closer than it looks, and this app gets used under floodlights.
- **"Keep awake" toggle has no state.** [App.svelte:2890-2891](src/App.svelte#L2890-L2891) changes the label from "Keep awake" to "Awake" and nothing else — same grey, same weight. You cannot tell at a glance whether the screen lock is held. It also eats ~110 px of header width on a phone where it should be an icon.
- **Possession Analysis opens as a wall of disabled controls** — "Start draft session", "Discard draft", "Save preset", "Apply preset", "CSV", "Snapshot" all render greyed at rest. First impression is a broken screen.
- **"Show paths" is filed under `SHOW ONLY:`** alongside two genuine filters. It is a display toggle, not a filter — category error in the control grouping.
- **Possession Analysis duplicates the half selector** — "All halves / First half / Second half / Extra time" in the Analysis View, and "First half / Second half / Extra time" in the Session Builder, meaning different things.
- **Header repeats the date**: "Clontarf v Vincents (2026-03-25)" with "2026-03-25" directly beneath it.
- **`FILTERED: [1 match] [Clear]`** — "1 match" reads as a result count, not a filter description. And `Clear` / `Reset` / `Filters · 1 ▼` are three overlapping affordances for the same filter state.
- **Two segmented-control styles** coexist: square-ish (`Both / Ours / Theirs` in analytics) and fully rounded pills (Possession Analysis). Same interaction, different visual language.
- **Live and Digest present the same score differently** — side-by-side with a centre "Level" chip in Live, stacked vertically in Digest.
- **Tactical Board disabled states are illegible.** "Undo", "Clear marks", "Show all" are grey-on-grey, and "Hide player" / "Reset positions" look disabled but are not. "Play" in the bottom bar is pale blue and reads as disabled.
- **Tactical Board teams are distinguished by colour alone** (red / amber counters, with a blue and a green keeper and no legend), and both teams use the same 1–15 numbering, so adjacent counters like red-5 and amber-15 are hard to separate at a glance.
- **`.re-hint` "Tap to edit"** at 1.41:1 is effectively invisible, which means the recent-events strip reads as a static list rather than a set of edit affordances.

---

## Recommended order

1. **Fix the phone capture layout** (§1.1) and add a portrait-phone case to `layout.spec.js`. Nothing else ships until this does.
2. **Fix the phone header** (§1.2).
3. **Fix the sticky Save bar overlap** (§2.1) — one line of `padding-bottom`.
4. **Introduce `:root` design tokens** (§3.4), and fix the §2.3 contrast failures as you go. Doing tokens first makes the contrast pass a handful of edits instead of a hundred.
5. **Add a global `:focus-visible` style** (§2.2) — one rule, applied once, in `app.css`.
6. **Raise touch targets to 44 px** in the capture form (§2.4).
7. **Add headings, `<main>`, and tab semantics** (§2.5).
8. Then the medium items — starting with TEAM/OUTCOME disambiguation (§3.1), which is the one that corrupts data rather than merely annoying.

## What is working

Worth saying plainly, because it should not get lost:

- The **Tactical Board** is excellent. Clear mode banner, sensible tool rail, legible counters, good use of full-bleed dark presentation. It is the most finished thing in the app.
- The **Live panel**'s score display, `Level` chip and kickout retention tiles are exactly right — large, glanceable, correctly prioritised.
- **Empty states are thoughtful** almost everywhere ("Start a draft session to begin logging possession events.", "No saved sessions yet for this match.").
- The **Shots stat tile row** (Total / Scored / Goal chances / Point attempts, with `2 → 2` notation) is a genuinely good piece of information design.
- The **visual-language document** is a real asset. The gaps in §3.7 and §3.8 are the implementation drifting from it, not the grammar being wrong.
